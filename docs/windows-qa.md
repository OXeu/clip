# Windows 第一轮验收

这份清单区分自动化已覆盖的逻辑与必须在 Windows 桌面 / NVIDIA 硬件上执行的检查。未执行的项目不得标记为已通过。

## 自动化

- `dotnet run --project tests/Clip.Tests -c Release -- --integration`：真实生成测试素材，验证剪辑内容、时长、音频对齐、失败和取消清理。
- `Clip.exe --startup-test`：Windows CI 执行正常启动，包括 FFmpeg / NVIDIA 检测，再创建导出窗口，进行分割 / 删除 / 撤销，渲染 `smoke-ui.png` 并写入成功标记。只检测退出码不足以通过此检查。`--smoke-test` 仍可用于单独验证布局；它不覆盖服务初始化。
- 空格焦点回归检查随上述 UI 验证执行：通过右键菜单删除并回到时间轴后，空格按下 / 松开只播放或暂停，片段和撤销记录不变；同时覆盖播放控制、导出按钮及下拉箭头、预览未就绪和忙碌状态。有视频素材时检查播放状态切换。
- 时间轴菜单回归随上述 UI 验证执行：从片段、空轨、标尺和面板底部打开统一菜单，验证右键选中目标、分割 / 删除 / 撤销 / 重做以及忙碌禁用状态。有真实素材时通过原生右键事件验证菜单入口，并保存菜单截图；Linux 构建不会执行这些 WPF 交互检查。
- `Clip.exe --startup-failure-test`：在 WPF 初始化前主动抛出测试异常，CI 要求退出码为 1，且日志中包含对应异常，防止错误发生后无诊断信息。
- 带真实视频的 `--startup-test` 还验证原生播放时钟前进时连续按两次 S，不调用暂停或重定位；通过路由事件检查 S / X / Delete 和横向滚轮，检查 Shift / Ctrl 滚轮的鼠标锚点与缩放边界。没有视频的 `--smoke-test` 不声称验证真实播放。
- 多轨验证使用两个不同方向 / 帧率 / 音轨配置的素材，通过 Windows 原生鼠标事件跨轨拖放、轨内重排及点击空白选轨；检查候选轨可导出、片段选择不能代替整轨选择、复制分流、命名与输入保护、候选轨连续预览和跨素材续播。FFmpeg 集成测试导出指定候选轨的命名副本，并以其他轨道缺失文件的方式确保不会读取无关轨道；同时保留静音补齐、变速时长及保持音调验证。
- 品牌移除回归：空态和导入后的页头无品牌块、分隔线或空占位，剪辑摘要保持 24 DIP 左对齐；主窗口、导出和检查更新窗口验证原生标题栏不含 Clip、不显示图标，独立更新进度窗口也覆盖标题和窗口样式检查。

## Windows 桌面

1. 在 100%、150% 缩放的 Windows 10/11 上运行发布包，检查主窗口、导出设置不裁切；片段属性面板及其占位完全消失，预览占满内容行；时间轴和预览面板均无 header 或空白占位，标尺和预览画面从各自面板顶部开始；没有缩放指示器和“适应”按钮。
2. 一次导入多个横屏 / 竖屏、有声 / 无声、不同帧率的素材，确认每个素材进入独立候选轨、主轨仍为空、导出已可用。只有一条非空轨道时不显示下拉箭头，多条时在导出按钮内部右侧显示箭头，列表按画布顺序列出所有非空轨道。单击片段不能指定导出轨道；点击轨道行内空白处后整行高亮，直接导出该轨道。未选整轨且有多条可导出轨道时，点击导出应先展开列表。重复测试中文、空格、单引号文件名，直接拖入及多参数命令行导入。
3. 确认时间轴左侧无主轨 / 候选名称、说明及原有宽占位，顶部无分割、删除、撤销、重做按钮。在片段、空轨、标尺及面板空白处右键，显示编辑菜单；无选中片段时删除、复制、命名禁用，无历史时撤销 / 重做禁用，导入或导出期间全部禁用。右键另一片段后操作应作用于该片段，空白处右键不改变选择和播放头。播放视频，在 2 秒和 4 秒附近按 S，确认立即分割、播放按钮保持暂停图标、声音和播放头连续前进；暂停后 S 仍可分割并保持暂停。分别用 X、Delete、右键菜单删除并通过菜单撤销 / 重做；播放跨接点确认跳过被删内容。
4. 拖动候选片段到主轨、主轨到候选轨，并在同轨前后重排；检查插入线、片段身份、内容范围及撤销 / 重做。拖到窗口外或按 Escape 取消应不改变项目。清空任一轨道后该轨道从导出列表移除，撤销后恢复；仍有其他非空轨道时导出保持可用。
5. 鼠标放在标尺和片段上分别测试：滚轮横向滚动；Shift + 滚轮（或 Ctrl + 滚轮）围绕鼠标位置缩放。测试高精度滚轮、小幅滚动、两端边界及最大/最小缩放；缩到最小时显示完整时间轴；播放中缩放、滚动不得暂停。滚动到尾部，验证分割与播放头位置一致。
6. 在导出尺寸输入框输入包含 S、X 的文本、按 Delete 编辑文字，主时间轴不应改变；Ctrl+X 仍为文本剪切。无效奇数宽高应有错误提示。
7. 分别从下拉列表和整轨选择导出主轨 / 候选轨，核对弹窗中的轨道名称、片段数和时长。导出原画、720p、竖屏与自定义尺寸，核对时长、画面比例和声音；尺寸 / 帧率默认参考所选轨道首个素材。所选轨道混合无声与有声素材时，无声区间必须为静音，不能混入其他轨道的视频或音轨。已有目标和源文件均不得覆盖。
8. 导出长视频时取消，确认界面恢复且目标目录没有 `.clip-*.mp4`。编码过程中关闭窗口应取消并等待清理。
9. 导入系统不支持的编码，确认自动生成兼容预览，可取消，导出仍使用原始素材；Windows N 版确认媒体功能包相关错误可理解。
10. 设置中添加右键菜单，关闭应用后在资源管理器右键视频打开。在 Windows 11“显示更多选项”检查。移除菜单后条目消失，默认视频播放器不变。
11. 通过右键菜单删除片段后不移动焦点，连续按下并松开空格，确认只播放 / 暂停，不再删除片段；长按空格只切换一次。用 Tab 聚焦播放、导出及导出箭头按钮后重复验证，焦点应保留；按钮仍可通过 Enter 或鼠标触发。聚焦时间轴后按 Shift+F10 或菜单键，应打开同一编辑菜单，Escape 关闭且不改变项目。
12. 分别复制 9.999、10、10.001 秒的片段：短片段紧跟原片段插入，原有后续片段顺延；10 秒及以上在原轨正下方新建候选轨道，不合并到已有下方轨道。复制后源范围和名称一致，副本可独立重命名；撤销删除整个复制结果（含新增轨道），重做恢复相同内容。命名窗口测试中文、长名称、空白校验、取消及 S / X / Delete / Ctrl+X 文字编辑保护，确认不改源文件、不影响同源片段，名称可撤销。
13. 在候选轨最后一段结束时应停止，不能转到别的轨道；轨内相邻素材不同时，预览应自动切源继续。超过四条轨道时检查冻结标尺、纵向滚动和拖拽边缘自动滚动；横向滚动后检查视口最左侧片段的选择和拖放，不应残留隐藏名称列的命中区；100% / 150% DPI 下核对拖拽落点。

## NVIDIA 实机

1. 使用支持 NVENC 的 NVIDIA GPU 与兼容驱动启动，状态栏必须基于实际单帧编码显示可用。至少覆盖一台 Turing 或更新显卡，确认 640×360 的检测画面不会触发旧版 128×128 的最小尺寸误判。
2. 在导出高级设置中确认只保留编码器选择及格式信息，没有 NVIDIA 硬件解码开关和检测说明段落。
3. 分别使用 NVENC 与 CPU 编码导出，验证声音和画面；NVENC 时任务管理器应能观察到 Video Encode 活动，导出路径不要求 Video Decode 活动。
4. 对显卡不支持解码但 FFmpeg 软件解码支持的素材，确认 NVENC 编码仍可配合软件解码导出。
5. 没有 NVIDIA 的电脑应使用 CPU 完成同样的导出，不出现假“GPU 可用”状态。
6. 在“设置 → NVIDIA 检测详情…”中确认 FFmpeg 路径、退出码、检测参数和原始错误与启动日志一致。使用驱动 API 不兼容的 FFmpeg、未编译 NVENC 的 FFmpeg 时，应分别提示具体原因，不能只显示未找到显卡。
7. 在“设置 → 重新检测 NVIDIA NVENC”中重试，确认状态栏和新打开的导出窗口同步更新；取消检测或选择无效 FFmpeg 目录后，应保留此前的有效配置和检测状态。

本地开发环境为 Linux。Windows 自动化验证结果与启动日志保存在 Actions 产物中；人工桌面交互、资源管理器和真实 NVIDIA 硬件验收仍须在上述环境执行。
