# Windows 第一轮验收

这份清单区分自动化已覆盖的逻辑与必须在 Windows 桌面 / NVIDIA 硬件上执行的检查。未执行的项目不得标记为已通过。

## 自动化

- `dotnet run --project tests/Clip.Tests -c Release -- --integration`：真实生成测试素材，验证剪辑内容、时长、音频对齐、失败和取消清理。
- `Clip.exe --startup-test`：Windows CI 执行正常启动，包括 FFmpeg / NVIDIA 检测，再创建导出窗口，进行分割 / 删除 / 撤销，渲染 `smoke-ui.png` 并写入成功标记。只检测退出码不足以通过此检查。`--smoke-test` 仍可用于单独验证布局；它不覆盖服务初始化。
- 空格焦点回归检查随上述 UI 验证执行：删除按钮保留焦点后，空格按下 / 松开只播放或暂停，片段和撤销记录不变；同时覆盖其他按钮、缩放滑块、预览未就绪和忙碌状态。有视频素材时检查播放状态切换。
- `Clip.exe --startup-failure-test`：在 WPF 初始化前主动抛出测试异常，CI 要求退出码为 1，且日志中包含对应异常，防止错误发生后无诊断信息。
- 带真实视频的 `--startup-test` 还验证原生播放时钟前进时连续按两次 S，不调用暂停或重定位；通过路由事件检查 S / X / Delete 和横向滚轮，检查 Shift / Ctrl 滚轮的鼠标锚点与缩放边界。没有视频的 `--smoke-test` 不声称验证真实播放。
- 多轨验证使用两个不同方向 / 帧率 / 音轨配置的素材，通过 Windows 原生鼠标事件跨轨拖放、轨内重排；检查空主轨禁止导出、独立速度、候选轨连续预览和主轨跨素材续播。FFmpeg 集成测试检查主轨画面 / 音频排除候选、静音补齐、变速时长及保持音调。
- 品牌移除回归：空态和导入后的页头无品牌块、分隔线或空占位，剪辑摘要保持 24 DIP 左对齐；主窗口、导出和检查更新窗口验证原生标题栏不含 Clip、不显示图标，独立更新进度窗口也覆盖标题和窗口样式检查。

## Windows 桌面

1. 在 100%、150% 缩放的 Windows 10/11 上运行发布包，检查主窗口、导出设置不裁切，调整窗口大小、时间轴面板高度和缩放。
2. 一次导入多个横屏 / 竖屏、有声 / 无声、不同帧率的素材，确认每个素材进入独立候选轨、主轨仍为空、导出不可用；分别选择候选片段核对预览来源。重复测试中文、空格、单引号文件名，直接拖入及多参数命令行导入。
3. 播放视频，在 2 秒和 4 秒附近按 S，确认立即分割、播放按钮保持暂停图标、声音和播放头连续前进；暂停后 S 仍可分割并保持暂停。左键选择中间片段，分别用 X、Delete、右键删除并撤销验证；播放跨接点确认跳过被删内容。
4. 拖动候选片段到主轨、主轨到候选轨，并在同轨前后重排；检查插入线、片段身份、内容范围及撤销 / 重做。拖到窗口外或按 Escape 取消应不改变项目。清空主轨后即使候选轨仍有视频，导出也应禁用。
5. 鼠标放在标尺和片段上分别测试：滚轮横向滚动；Shift + 滚轮（或 Ctrl + 滚轮）围绕鼠标位置缩放。测试高精度滚轮、小幅滚动、两端边界、最大/最小缩放及“适应”；播放中缩放、滚动不得暂停。滚动到尾部，验证分割与播放头位置一致。
6. 在导出尺寸输入框输入包含 S、X 的文本、按 Delete 编辑文字，主时间轴不应改变；Ctrl+X 仍为文本剪切。无效奇数宽高应有错误提示。
7. 导出原画、720p、竖屏与自定义尺寸，核对时长、画面比例、声音及候选轨排除；尺寸 / 帧率默认参考主轨首个素材。主轨混合无声与有声素材时，无声区间必须为静音，不能串入候选音轨。已有目标和源文件均不得覆盖。
8. 导出长视频时取消，确认界面恢复且目标目录没有 `.clip-*.mp4`。编码过程中关闭窗口应取消并等待清理。
9. 导入系统不支持的编码，确认自动生成兼容预览，可取消，导出仍使用原始素材；Windows N 版确认媒体功能包相关错误可理解。
10. 设置中添加右键菜单，关闭应用后在资源管理器右键视频打开。在 Windows 11“显示更多选项”检查。移除菜单后条目消失，默认视频播放器不变。
11. 鼠标点击“删除”后不移动焦点，连续按下并松开空格，确认只播放 / 暂停，不再删除片段；长按空格只切换一次。用 Tab 聚焦分割、撤销、播放按钮和缩放滑块后重复验证，焦点应保留；按钮仍可通过 Enter 或鼠标触发。
12. 单片段分别设置 0.1、0.5、1.25、2、8 倍；核对时间轴长度、源帧分割位置及导出时长、声音音调。测试速度文本框内 S / X / Delete / Ctrl+X 不触发剪辑；0、负数、NaN 和超限值显示内联错误而不改变项目。候选片段变速不得改变主轨时长。
13. 在候选轨最后一段结束时应停止，不能转到别的轨道；轨内相邻素材不同时，预览应自动切源继续。超过四条轨道时检查冻结名称 / 标尺、纵向滚动和拖拽边缘自动滚动；100% / 150% DPI 下核对拖拽落点。

## NVIDIA 实机

1. 使用支持 NVENC 的 NVIDIA GPU 与兼容驱动启动，状态栏必须基于实际单帧编码显示可用。至少覆盖一台 Turing 或更新显卡，确认 640×360 的检测画面不会触发旧版 128×128 的最小尺寸误判。
2. 对支持的 H.264 素材选 NVENC + 硬件解码导出，验证声音和画面，任务管理器观察 Video Decode / Video Encode 引擎活动。
3. 单独关闭硬件解码，保持 NVENC 编码并导出，确认回退路径正常。
4. 使用显卡不支持解码的编码格式，确认明确报错，能够关闭硬件解码重试。应用不应将硬解失败悄悄当作硬解成功。
5. 没有 NVIDIA 的电脑应使用 CPU 完成同样的导出，不出现假“GPU 可用”状态。
6. 在“设置 → NVIDIA 检测详情…”中确认 FFmpeg 路径、退出码、检测参数和原始错误与启动日志一致。使用驱动 API 不兼容的 FFmpeg、未编译 NVENC 的 FFmpeg 时，应分别提示具体原因，不能只显示未找到显卡。
7. 在“设置 → 重新检测 NVIDIA NVENC”中重试，确认状态栏和新打开的导出窗口同步更新；取消检测或选择无效 FFmpeg 目录后，应保留此前的有效配置和检测状态。

本地开发环境为 Linux。Windows 自动化验证结果与启动日志保存在 Actions 产物中；人工桌面交互、资源管理器和真实 NVIDIA 硬件验收仍须在上述环境执行。
