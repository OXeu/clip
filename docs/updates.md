# 更新 Clip

在“设置 → 检查更新…”中查看可用版本，点击“更新并重启”即可下载、校验并安装。**更新前先导出需要保留的剪辑**，当前不支持保存项目。取消编辑器的关闭确认，会取消这次安装。

## 选择更新通道

| 通道 | 获取的版本 |
| --- | --- |
| 默认 | GitHub 最新正式 Release，不包含草稿或预发布 |
| Dev 模式（GitHub Actions） | 默认分支上成功构建、产物未过期的 Windows 版本，不包含 PR 构建 |

Dev 模式在设置菜单中切换，重启后仍保留。程序每次启动会在后台检查一次更新，发现新版本时在设置菜单提示；不会自动安装。若尚无正式 Release，可切换到 Dev 通道。

## GitHub 访问权限

公开 Release 无需令牌。访问私有仓库或下载 Actions 构建时，可能需要为目标仓库授予 **Contents: Read** 和 **Actions: Read** 权限的 GitHub 令牌。

在更新窗口展开“下载与访问设置”，输入令牌后点击“检查更新”；也可通过 `CLIP_GITHUB_TOKEN` 环境变量提供。窗口输入的令牌仅保存在当前会话内存，不写入设置或日志。

检查失败时，根据窗口提示确认网络、令牌权限或构建是否过期。只有完整的 `Clip-win-x64.zip` 且附带 GitHub SHA-256 摘要，才可自动安装；源码包、单独的 EXE 和 7z 包不适用。

## 安装位置与备份

更新会替换当前 `Clip.exe` 所在目录中的文件，请确保该目录可写，并为下载包、解压内容和旧文件备份预留空间。

旧程序退出后，独立更新窗口完成替换并启动新版本。替换或启动进程失败时，会尝试恢复旧文件；如果恢复失败，窗口会显示备份位置。新进程启动后发生的崩溃不会触发回滚，可使用程序旁的 `Start-Clip-Diagnostics.cmd` 排查。

下载内容和备份保存在程序目录下的 `.clip-updates/<编号>/`。确认新版本正常、更新窗口已关闭后，可以删除对应编号的文件夹来释放空间。

发布版本的方法见[开发指南](development.md#打包发布)。
